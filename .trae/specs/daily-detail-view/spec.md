# 每日详情页规格说明

## 补充说明

### Why：为什么需要这个功能
当前系统在首页左侧 `DayTaskPanel` 提供了选中日期的任务快速预览，但存在以下不足：
1. 面板空间有限（仅 270px 宽），信息展示不充分，无法按计划分组展示任务。
2. 缺少独立的、以日期为中心的详情页，用户无法通过 URL 直接访问某一天（如 `/day/2026-06-02`）。
3. 没有前一天/后一天的导航功能，用户切换日期需反复点击日历。
4. 缺少当天学习时长的汇总展示。
5. 面板中的任务不可点击跳转到对应的计划详情页。
6. 每日详情页是 `check.md` 第 5 条明确要求的核心功能，当前完全缺失。
7. 用户需要将大纲级任务进一步拆分为可逐个勾选的实施步骤，且能手动增删改，以便追踪更细粒度的完成进度。

因此需要一个独立的每日详情页，以日期为中心组织全部任务信息，并提供完整的浏览、切换、完成状态交互、子任务拆分和手动管理能力。

### What Changes：需要改变什么
- 新增 `/day/:date` 路由和 `DayDetailView.vue` 页面组件。
- 改造 `DayTaskPanel.vue` 或首页日历点击行为：点击有任务的日期后跳转到 `/day/:date`。
- 每日详情页按计划分组展示当天所有任务。
- 每日详情页支持 checkbox 勾选完成，视觉反馈明确（删除线、颜色变淡）。
- 每日详情页支持前一天/后一天导航。
- 每日详情页中的任务可点击跳转到对应计划详情页。
- 每日详情页展示当天总学习时长。
- 用户可**手动创建、修改、删除**子任务，也可让 AI 自动生成子任务。
- 用户手动创建的子任务记录 `source: 'user'`，AI 生成的记录 `source: 'ai'`。
- 「重新拆分」仅清除 AI 生成的子任务并重新生成，用户手动创建的子任务保留不被覆盖。
- 子任务全部勾选后父任务自动完成，父任务完成后子任务全部完成（级联规则）。
- 新增 `study_subtasks` 数据库集合和对应云函数 API（`generateSubtasks`、`createSubtask`、`updateSubtask`、`deleteSubtask`、`updateSubtaskStatus`）。

### Requirements：系统应该满足什么要求
- 系统 SHALL 提供 `/day/:date` 路由。
- 系统 SHALL 按计划分组展示当天任务，提供前后日期导航。
- 系统 SHALL 为每个任务提供完成状态 checkbox 及其视觉反馈。
- 系统 SHALL 支持用户手动添加子任务（在任务下方输入框输入标题后回车）。
- 系统 SHALL 支持用户修改已有子任务的标题（点击编辑按钮，修改后回车或失焦保存）。
- 系统 SHALL 支持用户删除已有子任务（点击删除按钮，确认后移除）。
- 系统 SHALL 为每个子任务标注来源：`user`（用户手动创建）或 `ai`（AI 生成）。
- 系统 SHALL 在 AI「重新拆分」时仅删除 `source='ai'` 的子任务并重新生成，保留 `source='user'` 的子任务。
- 系统 SHALL 在级联规则中：所有子任务完成 → 父任务自动完成；父任务完成 → 所有子任务自动完成。

### Scenarios：用户在什么情况下看到什么结果
- 当用户点击任务下的「+ 添加步骤」输入框，输入"阅读文档第3章"并回车，该子任务立即出现并持久化，标记为用户创建。
- 当用户点击子任务旁的编辑按钮，修改标题后回车，子任务标题即时更新并持久化。
- 当用户点击子任务旁的删除按钮，子任务从列表中移除并持久化删除。
- 当用户已有 2 个用户手动创建的子任务 + 3 个 AI 生成的子任务，点击「重新拆分」时，仅 3 个 AI 子任务被清除并重新生成，用户创建的 2 个保留不变。
- 当用户逐个勾选子任务，最后一个子任务被勾选时，父任务自动标记为完成。
- 当用户直接勾选父任务完成时，所有子任务自动勾选完成。

## 1. 项目概述

### 1.1 背景
`check.md` 第 4、5、6 条明确要求：
> 用户点击日历上的某一天后，系统应提供当天任务的快速预览。
> 每日详情页需要以"日期"为中心组织信息。
> 在每日详情页面，可以自行创建，也可让AI自动生成任务的详细实施步骤或具体内容，列出详细实施步骤或具体内容后也可依次勾选，某任务的步骤全部勾选后，该任务自动勾选完成。

### 1.2 目标
构建独立的每日详情页 `/day/:date`，以日期为中心整合展示所有计划的任务，提供完整的浏览、完成状态交互、计划导航能力，并支持手动和 AI 两种方式管理子任务。

### 1.3 设计原则
- 日期中心、分组清晰、导航便捷、状态持久、链接互通
- 混合来源：子任务可来自用户手动创建或 AI 生成，互不覆盖
- 来源可区分：用户创建的子任务优先保留，AI 生成的可被重新生成替换

## 3. 功能需求

### 3.1 路由设计
- 路径: `/day/:date`，组件: `DayDetailView`，参数: `date`（`YYYY-MM-DD`）
- 格式不符时重定向到首页。

### 3.2 页面布局

```
┌────────────────────────────────────────────┐
│ ← 返回工作台   2026年6月2日 星期一          │
│ ◀ 前一天  ▶ 后一天         总学习时长：180分钟│
├────────────────────────────────────────────┤
│ ▎React 基础入门                              │
│   ☐ [高] 组件与JSX学习          90分钟       │
│     [AI 拆分步骤]                             │
│     ├ ☐ 阅读官方文档第3章                     │  ✏️  ×
│     ├ ☑ ~~完成配套练习1-3题~~                  │  ✏️  ×
│     └ ☐ 整理核心概念笔记                       │  ✏️  ×
│     [+ 添加步骤________]                      │
│     已完成 1/3 步                              │
│                                              │
│ 空状态：当天没有学习任务                      │
└────────────────────────────────────────────┘
```

### 3.3 完成状态交互（父任务 + 子任务）

#### 3.3.1 父任务勾选
- 乐观更新 → `updateTaskStatus` → 勾选完成时批量标记所有子任务为完成。

#### 3.3.2 子任务勾选
- 乐观更新 → `updateSubtaskStatus` → 全部子任务完成时自动调用 `updateTaskStatus` 标记父任务完成。

#### 3.3.3 级联规则
- 子任务全完成 → 父任务自动完成。
- 父任务完成 → 所有子任务自动完成。
- 取消父任务完成 → 子任务保持当前状态不变。

### 3.4 子任务管理

#### 3.4.1 子任务来源标识
子任务新增 `source` 字段：
- `'user'` — 用户手动创建
- `'ai'` — AI 自动生成

#### 3.4.2 手动创建子任务
- 子任务列表底部有一个「+ 添加步骤」输入框。
- 用户输入标题后按回车键 → 调用 `createSubtask(taskId, title)`，`source='user'`。
- 新建的子任务插入到列表末尾（`sortOrder = max + 1`），即时显示。

#### 3.4.3 修改子任务标题
- 每个子任务行末尾有编辑按钮（✏️）。
- 点击编辑按钮 → 标题变为可编辑输入框。
- 修改后按回车或失焦 → 调用 `updateSubtask(subtaskId, { title })` 持久化。

#### 3.4.4 删除子任务
- 每个子任务行末尾有删除按钮（×）。
- 点击删除按钮 → 调用 `deleteSubtask(subtaskId)` 持久化删除。
- 删除后即时从列表中移除。

#### 3.4.5 AI 拆分步骤
- 按钮文案：无子任务时「AI 拆分步骤」，已有子任务时「重新拆分」。
- 首次 AI 拆分：调用 `generateSubtasks(taskId)`，生成 3-5 个 `source='ai'` 的子任务。
- **重新拆分行为**：
  - 调用 `generateSubtasks(taskId)`。
  - 云函数仅删除该任务下所有 `source='ai'` 的旧子任务。
  - **保留**所有 `source='user'` 的用户手动创建的子任务。
  - 生成新的 AI 子任务并写入数据库。
- AI prompt 同上。

### 3.5 前一天/后一天导航
- 前端根据 `date` 参数计算 ±1 天，`router.push` 到新日期。

## 4. 数据模型

### 4.1 SubTask 类型

```ts
interface SubTask {
  _id: string
  taskId: string
  planId: string
  title: string
  completed: boolean
  source: 'user' | 'ai'     // 来源标识
  sortOrder: number
  createdAt: string
  updatedAt: string
}
```

### 4.2 数据库集合：`study_subtasks`

```json
{
  "_id": "sub_xxx",
  "taskId": "task_xxx",
  "planId": "plan_xxx",
  "title": "阅读官方文档第3章",
  "completed": false,
  "source": "ai",
  "sortOrder": 0,
  "createdAt": "2026-06-02T10:00:00.000Z",
  "updatedAt": "2026-06-02T10:00:00.000Z"
}
```

### 4.3 云函数 API 设计

| API | 请求 | 响应 | 说明 |
|-----|------|------|------|
| `generateSubtasks` | `{ taskId }` | `{ subtasks: SubTask[] }` | 仅删 AI 旧子任务，生成新 AI 子任务 |
| `createSubtask` | `{ taskId, planId, title }` | `{ subtask: SubTask }` | 用户手动创建 |
| `updateSubtask` | `{ subtaskId, title }` | `{ success: boolean }` | 用户修改标题 |
| `deleteSubtask` | `{ subtaskId }` | `{ success: boolean }` | 用户删除子任务 |
| `updateSubtaskStatus` | `{ subtaskId, completed }` | `{ success: boolean }` | 更新完成状态 |

## 5. 与现有 DayTaskPanel 的关系

推荐 **方案 A**：保持现有交互，面板内新增「查看完整详情 →」链接跳转到 `/day/:date`。

## 6. 验收标准

1. `/day/2026-06-02` 路由可访问，按计划分组展示任务。
2. 任务 checkbox 勾选/取消，有删除线视觉反馈，状态持久化。
3. 前一天/后一天导航正常。
4. 用户可在任务下通过「+ 添加步骤」输入框手动创建子任务。
5. 用户可点击编辑按钮修改子任务标题。
6. 用户可点击删除按钮删除子任务。
7. AI 首次拆分生成 3-5 个子任务，`source='ai'`。
8. 「重新拆分」仅替换 `source='ai'` 的旧子任务，保留用户手动创建的子任务。
9. 所有子任务勾选完成后父任务自动完成。
10. 父任务勾选完成时所有子任务自动完成。
11. 子任务数据及其来源标识刷新后保留。
12. AI 拆分失败时有错误提示，可重试。
